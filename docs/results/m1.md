# M1 test results

Recorded 2026-10-06 on the author's machine (Windows 11, Terraform 1.16.5, hashicorp/aws provider
6.67.0, Go 1.25.6, hashicorp/hcl v2.25.0). CI re-runs everything on Ubuntu with Go 1.26 and the
same Terraform version, downloaded by `scripts/terraform.sh` and checked against HashiCorp's
SHA-256 sums.

## Tests: 16 passed, 0 failed

Command: `make test`: 7 Go tests, then `terraform test` with 9 runs. No AWS account is used:
both AWS providers are mocked, with realistic ARNs so the provider's own argument validation
still runs.

| Suite | Tests | What it proves |
|---|---|---|
| `terraform test`: both regions | 1 run, 5 assertions | Same number of availability zones, the same image digest and engine version in both regions, HTTPS with the TLS 1.3 policy, plain HTTP only redirects, roles wired to the right modules |
| `terraform test`: warm standby | 1 run | The standby runs one task and one database instance; the primary three tasks and two instances |
| `terraform test`: global database | 1 run, 6 assertions | Both clusters join one global database, which is encrypted and deletion-protected; each region uses its own rotating KMS key, which lets that region's CloudWatch Logs encrypt only the stack's log group; only the primary has credentials; deletion protection and at least seven days of backups |
| `terraform test`: exposure | 1 run | No public database instances, no public IPs on tasks, the database only accepts the API's security group, logs kept 30 days |
| `terraform test`: refused inputs | 5 runs | The same region twice, a standby of zero, a standby larger than the primary, an image tag instead of a digest, overlapping VPC ranges |
| `internal/parity` (Go) | 4 | The repository's two stacks match; stacks differing only by role are equivalent; a different image, a setting on one side only, swapped roles, a hard-coded value, a different module and the standby wired to the primary's provider are each reported; missing or unparsable files are errors |
| `internal/cost` (Go) | 3 | A known sizing gives the hand-computed monthly cost; sizing is read from the variable defaults; malformed sizing is an error |

Lint: `gofmt`, `go vet`, `terraform fmt -check` and `terraform validate`: clean. Audit: every Go
module in `go.mod` is free of known vulnerabilities on OSV.dev (golang.org/x/text and
golang.org/x/mod were raised to fixed versions), and `govulncheck` reports no vulnerable code.

## Do the tests catch real mistakes?

| Injected change | Caught by |
|---|---|
| Database instances made publicly accessible | `nothing_private_is_reachable_from_the_internet` |
| Standby cluster pointed away from the global database | `both_clusters_belong_to_one_encrypted_global_database` (and the parity checker) |
| API tasks given public IPs | `nothing_private_is_reachable_from_the_internet` |

Writing the documentation also surfaced a bug the mocks could not see: the API log group was
encrypted with the region's KMS key, but the key policy did not allow CloudWatch Logs to use it,
so a real apply would have failed. The key now has that statement, limited to the stack's log
group, and a test asserts it.

## What the numbers say

- **The two regions cannot drift silently.** Both are one module; the checker rejects any
  difference beyond the role (including a standby wired to the primary's provider), and the tests
  pin the security settings in both.
- **A warm standby costs about half the primary.** With the default sizing the estimate is
  263.94 USD a month against 489.78 USD (54%), before usage-based charges. Most of it is the one
  Aurora instance (189.80 USD); the NAT gateway, load balancer and the single task are the price
  of a standby that is already serving health checks when a failover starts.
- **These are list-price estimates**, copied in 2025 and labelled as such; the real bill for a
  week of the lab is part of M3, together with measured RTO and RPO.

## Quality control (DMAIC)

| Phase | This repository |
|---|---|
| Define | A standby region drifts from the primary when it is never exercised, and checking it usually means paying for a real deployment; this affects teams planning disaster recovery on AWS. M1 counts when one Terraform module builds both regions, an Aurora Global Database joins them, validation refuses configurations that would not fail over, mocked `terraform test` checks both regions, and a Go checker rejects drift and estimates each stack's fixed cost ([RFC 0001](../rfc/0001-design.md)). |
| Measure | `make test` (7 Go tests and 9 `terraform test` runs against mocked AWS providers), `make check`, `make lint` and an OSV.dev and `govulncheck` audit on Windows 11 with Terraform 1.16.5, plus three injected mistakes. 16 tests passed, 0 failed; the parity check compared 14 settings and found only role differences; the standby's estimated fixed cost is 263.94 USD a month, 54% of the primary's 489.78 USD, at 2025 list prices. |
| Analyze | Three defects were found: the KMS key policy did not let CloudWatch Logs use the key, so a real apply would have failed (the mocks could not see it); the parity checker treated a standby wired to the primary's provider as identical after normalisation; and `golang.org/x/text` and `golang.org/x/mod` had known advisories. RTO and RPO are not measured yet (M3). |
| Improve | The key policy now allows CloudWatch Logs for the stack's log group only, with a test that asserts it; the checker gained the rule that each side may refer only to its own role (ADR 0003); `x/text` and `x/mod` were raised to fixed versions, after which OSV.dev and `govulncheck` were clean. |
| Control | The `ci` workflow's `build` job runs `make ci` (gofmt, `go vet`, `terraform fmt -check`, `terraform validate`, the Go tests, `terraform test` and the parity check) and `make audit` (`govulncheck`), with Terraform downloaded at a pinned version and checked against HashiCorp's SHA-256 sums. In the code, Terraform validation refuses the same region twice, a standby of zero, a standby larger than the primary, image tags instead of digests and overlapping VPC ranges, and the database password is kept in Secrets Manager, not in variables or state. |
